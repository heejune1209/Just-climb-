### 1) **스테이지 클리어 + Redis 하이브리드 랭킹 업데이트 흐름**
**게임플레이 → 기록 갱신 → Redis 우선 저장 → DB 백그라운드 저장 → 실시간 랭킹 업데이트**

```mermaid
sequenceDiagram
    participant Player as 🎮 Player
    participant StageSystem as 🎯 StageManager
    participant RankingMgr as 🏆 RankingManager
    participant Steam as 🚂 SteamAuthManager
    participant Server as 🌐 ASP.NET Server
    participant RankingAPI as 📊 RankingController
    participant HybridService as ⚡ HybridRankingService
    participant RedisService as 🚀 RedisRankingService
    participant DatabaseService as 🗄️ DatabaseRankingService
    participant Redis as ⚡ Redis Cache
    participant Database as 🗄️ SQL Database

    Note over Player, Database: 1단계: 스테이지 클리어 및 기록 갱신
    Player->>StageSystem: 스테이지 클리어 (gems: 3/3, time: 25.5s, deaths: 2)
    activate StageSystem
    
    StageSystem->>StageSystem: 기존 최고 기록과 비교 (이전: 30.2s, 5deaths)
    StageSystem->>StageSystem: ✅ 신기록 달성 (clearTime: 25.5s ↓, deathCount: 2 ↓)
    
    StageSystem->>RankingMgr: OnBestTimeUpdated(stageNum: 1, clearTime: 25.5s)
    activate RankingMgr
    deactivate StageSystem

    Note over Player, Database: 2단계: Steam 닉네임 조회 및 서버 전송
    RankingMgr->>Steam: GetSteamDisplayName()
    activate Steam
    Steam-->>RankingMgr: "JustClimber_2024"
    deactivate Steam
    
    RankingMgr->>RankingMgr: 📋 기록 업데이트 요청 생성
    
    RankingMgr->>Server: POST /api/ranking/{userId}/record JWT Authorization Header
    activate Server
    
    Server->>RankingAPI: UpdateUserRecord(userId, requestDto)
    activate RankingAPI
    
    RankingAPI->>RankingAPI: ✅ 입력 검증 통과 (stageNum: 1~10, clearTime > 0, etc.)
    RankingAPI->>HybridService: UpdateUserRecordAsync(userId, request)
    activate HybridService
    
    Note over Player, Database: 3단계: 🚀 Redis 우선 저장 + DB 백그라운드 저장 (하이브리드)
    par Redis 실시간 업데이트 (최고 성능)
        HybridService->>RedisService: UpdateUserRecordAsync(userId, request)
        activate RedisService
        
        RedisService->>Redis: ZADD stage_1_cleartime JustClimber_2024 25.5
        activate Redis
        RedisService->>Redis: ZADD stage_1_deathcount JustClimber_2024 2
        RedisService->>Redis: HMSET userdata:stage:1:user:{userId} name "JustClimber_2024" clearTime 25.5 deathCount 2
        Redis-->>RedisService: ✅ Redis 업데이트 완료 (O(log n) 성능)
        deactivate Redis
        
        RedisService-->>HybridService: ✅ Redis 저장 성공 (즉시 응답)
        deactivate RedisService
    and DB 백그라운드 저장 (데이터 안정성)
        HybridService->>DatabaseService: UpdateUserRecordAsync(userId, request)
        activate DatabaseService
        
        DatabaseService->>Database: BEGIN TRANSACTION
        activate Database
        DatabaseService->>Database: UPSERT UserStageRecord SET clear_time=25.5, death_count=2, display_name='JustClimber_2024'
        DatabaseService->>Database: UPDATE last_updated = NOW()
        DatabaseService->>Database: COMMIT TRANSACTION
        Database-->>DatabaseService: ✅ DB 백그라운드 저장 완료
        deactivate Database
        
        DatabaseService-->>HybridService: ✅ DB 저장 성공 (백그라운드)
        deactivate DatabaseService
    end
    
    HybridService->>HybridService: 🎯 Redis 성공하면 즉시 응답 (실시간 성능 우선)
    HybridService-->>RankingAPI: ✅ 하이브리드 업데이트 완료
    deactivate HybridService
    
    RankingAPI-->>Server: HTTP 200 OK
    deactivate RankingAPI
    Server-->>RankingMgr: 기록 업데이트 성공
    deactivate Server
    
    RankingMgr->>RankingMgr: 🧹 해당 스테이지 캐시 무효화 (다음 조회 시 최신 데이터 로드)
    deactivate RankingMgr
```

### 2) **Redis 하이브리드 랭킹 조회 및 자동 마이그레이션 흐름**
**UI 요청 → Redis 우선 조회 → 없으면 DB 조회 후 Redis 마이그레이션 → 캐시 업데이트**

```mermaid
sequenceDiagram

    participant RankingMgr as 🏆 RankingManager
    participant Server as 🌐 ASP.NET Server
    participant RankingAPI as 📊 RankingController

    participant RedisService as 🚀 RedisRankingService
    participant DatabaseService as 🗄️ DatabaseRankingService
    participant Redis as ⚡ Redis Cache
    participant Database as 🗄️ SQL Database

    Note over UI, Database: 랭킹 UI에서 데이터 요청

    activate RankingMgr

    RankingMgr->>RankingMgr: 🔍 로컬 캐시 확인
    alt 캐시에 데이터 있음

    else 캐시 없음 - 서버 조회

            RedisService->>Redis: ZADD stage_1_deathcount ...
            activate Redis
            Redis-->>RedisService: ✅ 마이그레이션 완료
            deactivate Redis

            deactivate RedisService
        end

        deactivate RedisService

        HybridService->>HybridService: 📋 응답 구성
        HybridService-->>RankingAPI: RankingResponseDto
        deactivate HybridService

        RankingAPI-->>Server: HTTP 200 + JSON
        deactivate RankingAPI
        Server-->>RankingMgr: 랭킹 데이터 수신
        deactivate Server

        RankingMgr->>RankingMgr: 💾 로컬 캐시에 저장

```

### 3) **서버 시작 시 자동 DB → Redis 마이그레이션 흐름**
**서버 부팅 → Redis 초기화 → 전체 스테이지 데이터 마이그레이션 → 랭킹 시스템 준비 완료**

```mermaid
sequenceDiagram
    participant Server as 🖥️ Server Startup
    participant Program as ⚙️ Program.cs
    participant HybridService as ⚡ HybridRankingService
    participant RedisService as 🚀 RedisRankingService
    participant DatabaseService as 🗄️ DatabaseRankingService
    participant Redis as ⚡ Redis Cache
    participant Database as 🗄️ SQL Database

    Note over Server, Database: 서버 시작 시 자동 마이그레이션 프로세스
    Server->>Program: 서버 부팅 시작
    activate Program
    
    Program->>Program: 🏗️ DI 컨테이너 설정 (HybridRankingService, RedisRankingService, DatabaseRankingService 등록)
    
    Program->>RedisService: InitializeAsync()
    activate RedisService
    
    RedisService->>Redis: PING
    activate Redis
    Redis-->>RedisService: PONG
    deactivate Redis
    
    RedisService-->>Program: ✅ Redis 연결 성공
    deactivate RedisService
    
    Note over Server, Database: 백그라운드 전체 마이그레이션 시작
    Program->>Program: 🔄 Task.Run() 백그라운드 태스크 시작
    
    loop 전체 스테이지 (1~10)
        Program->>RedisService: MigrateFromDatabaseAsync(dbService, stageNumber)
        activate RedisService
        
        RedisService->>DatabaseService: GetAllStageRecordsAsync(stageNumber)
        activate DatabaseService
        
        DatabaseService->>Database: SELECT * FROM UserStageRecord WHERE stage_number = {stage}
        activate Database
        Database-->>DatabaseService: 📊 스테이지별 전체 기록 데이터
        deactivate Database
        
        DatabaseService-->>RedisService: List<UserStageRecord>
        deactivate DatabaseService
        
        RedisService->>Redis: ZADD stage_{num}_cleartime (모든 기록)
        activate Redis
        RedisService->>Redis: ZADD stage_{num}_deathcount (모든 기록)
        RedisService->>Redis: HMSET userdata:stage:{num}:user:{userId} (사용자 정보)
        Redis-->>RedisService: ✅ 스테이지 {num} 마이그레이션 완료
        deactivate Redis
        
        RedisService-->>Program: ✅ Stage {num} 완료
        deactivate RedisService
    end
    
    Program->>Program: 🎯 전체 마이그레이션 완료 (총 10개 스테이지 처리, Redis 랭킹 시스템 준비 완료)
    
    Program-->>Server: 🚀 서버 시작 완료 랭킹 시스템 운영 준비 완료
    deactivate Program
```

## **🎯 하이브리드 랭킹 시스템 특징**

### **⚡ Redis 기반 실시간 성능**
- **O(log n) 시간복잡도**: Redis Sorted Set으로 초고속 랭킹 처리
- **즉시 응답**: 기록 업데이트 시 Redis 성공하면 즉시 클라이언트 응답
- **실시간 조회**: 캐시된 랭킹 데이터로 밀리초 단위 조회 성능

### **🗄️ Database 기반 데이터 안정성**  
- **영구 저장**: 모든 기록이 SQL Database에 영구적으로 저장
- **백그라운드 저장**: Redis 업데이트 후 DB 저장을 백그라운드에서 처리
- **데이터 무결성**: Redis 실패 시 DB로 폴백하여 데이터 손실 방지

### **🔄 자동 마이그레이션 시스템**
- **서버 시작 시**: 전체 DB 데이터를 Redis로 자동 마이그레이션
- **런타임 마이그레이션**: Redis에 데이터가 없으면 DB에서 조회 후 즉시 캐시
- **백그라운드 처리**: 마이그레이션 작업이 클라이언트 응답에 영향 없음

### **🎮 클라이언트 호환성**
- **API 변경 없음**: 기존 `IRankingService` 인터페이스 유지
- **투명한 업그레이드**: 클라이언트 코드 수정 없이 성능 향상
- **기존 UI 유지**: `RankingManager`, `UI_Ranking` 등 모든 UI 그대로 사용

### **📊 모니터링 및 헬스체크**
- **랭킹 헬스체크**: `/api/v1/health/ranking` 엔드포인트로 Redis 상태 확인
- **실시간 로깅**: Redis/DB 각 단계별 상세 로깅 및 성능 추적
- **장애 복구**: Redis 장애 시 자동 DB 폴백 및 복구 시 재마이그레이션

## **🏆 업적 시스템 흐름**

### 4) **업적 달성 감지 및 해제 흐름**
**게임 이벤트 → AchievementIntegration → 조건 체크 → Steam API 호출 → 서버 동기화 → 알림 표시**

```mermaid
sequenceDiagram
    participant Player as 🎮 Player
    participant StageSystem as 🎯 StageManager
    participant Integration as 🔗 AchievementIntegration
    participant AchievementMgr as 🏅 AchievementManager
    participant SteamAPI as 🚂 Steam API
    participant DataMgr as 💾 DataManager
    participant Server as 🌐 ASP.NET Server
    participant AchievementAPI as 🏆 AchievementController
    participant AchievementService as ⚙️ AchievementService
    participant Database as 🗄️ SQL Database

    Note over Player, Database: 1단계: 게임 이벤트 발생 (스테이지 클리어)
    Player->>StageSystem: 스테이지 1 클리어 (무사망, 모든 젬 수집)
    activate StageSystem
    
    StageSystem->>Integration: AchievementIntegration.OnStageCleared(stage: 1, time: 25.5s, deaths: 0, gems: 3, total: 3)
    activate Integration
    deactivate StageSystem
    
    Integration->>AchievementMgr: _achievementManager.OnStageCleared(stage: 1, time: 25.5s, deaths: 0, gems: 3, total: 3)
    activate AchievementMgr
    deactivate Integration
    
    AchievementMgr->>AchievementMgr: 📋 업적 조건 체크 (첫 스테이지 클리어 ✅, 완벽주의자 무사망 ✅, 완벽한 수집가 모든 젬 ✅)

    Note over Player, Database: 2단계: Steam API를 통한 업적 해제
    loop 달성된 업적들 처리
        AchievementMgr->>SteamAPI: SetAchievement("NOVICE_CLIMBER")
        activate SteamAPI
        SteamAPI-->>AchievementMgr: ✅ Achievement Set Success
        
        AchievementMgr->>SteamAPI: StoreStats()
        SteamAPI-->>AchievementMgr: ✅ Steam 서버에 저장 완료
        deactivate SteamAPI
        
        AchievementMgr->>AchievementMgr: 💾 클라이언트 캐시 업데이트 achievementUnlocked["NOVICE_CLIMBER"] = true
        AchievementMgr->>AchievementMgr: 🔔 업적 달성 알림 표시 "🏆 업적 달성: 초보 등반가"
    end

    Note over Player, Database: 3단계: 서버 동기화 (백그라운드)
    AchievementMgr->>DataMgr: GenerateDelta("achievementUnlocked_NOVICE_CLIMBER", true)
    activate DataMgr
    DataMgr->>DataMgr: 📝 Delta 이벤트 큐에 추가 (5초 후 배치 처리)
    deactivate DataMgr
    
    Note over Player, Database: (5초 후 배치 동기화)
    DataMgr->>Server: POST /api/users/{userId}/state/delta { "deltas": [{"key": "achievementUnlocked_NOVICE_CLIMBER", "value": true}] }
    activate Server
    
    Server->>AchievementAPI: MergeDeltasAsync(userId, deltas)
    activate AchievementAPI
    
    AchievementAPI->>AchievementService: UpdateAchievementProgress(userId, achievementData)
    activate AchievementService
    
    AchievementService->>Database: UPDATE UserAchievement SET novice_climber = true WHERE user_id = '{userId}'
    activate Database
    Database-->>AchievementService: ✅ 업적 상태 업데이트 완료
    deactivate Database
    
    AchievementService-->>AchievementAPI: 동기화 성공
    deactivate AchievementService
    AchievementAPI-->>Server: HTTP 200 OK
    deactivate AchievementAPI
    Server-->>DataMgr: 서버 동기화 완료
    deactivate Server
    
    deactivate AchievementMgr
```

### 5) **업적 보상 수령 흐름**
**UI에서 보상 요청 → 서버 검증 → 재화 지급 → 상태 업데이트**

```mermaid
sequenceDiagram
    participant Player as 🎮 Player
    participant UI as 🖥️ UI_Achievement
    participant AchievementMgr as 🏅 AchievementManager
    participant CurrencyMgr as 💰 CurrencyManager
    participant DataMgr as 💾 DataManager
    participant Server as 🌐 ASP.NET Server
    participant AchievementAPI as 🏆 AchievementController
    participant AchievementService as ⚙️ AchievementService
    participant Database as 🗄️ SQL Database

    Note over Player, Database: 1단계: 플레이어가 보상 수령 요청
    Player->>UI: "보상 받기" 버튼 클릭 (NOVICE_CLIMBER)
    activate UI
    
    UI->>AchievementMgr: ClaimReward("NOVICE_CLIMBER")
    activate AchievementMgr
    
    AchievementMgr->>AchievementMgr: ✅ 조건 검증<br/>• 업적 달성 여부: true<br/>• 보상 수령 여부: false
    
    Note over Player, Database: 2단계: 서버에 보상 수령 요청
    AchievementMgr->>Server: POST /api/achievement/NOVICE_CLIMBER/claim-reward<br/>JWT Authorization Header
    activate Server
    
    Server->>AchievementAPI: ClaimReward("NOVICE_CLIMBER")
    activate AchievementAPI
    
    AchievementAPI->>AchievementAPI: 🔐 JWT 토큰에서 사용자 ID 추출
    AchievementAPI->>AchievementService: ClaimRewardAsync(userId, "NOVICE_CLIMBER")
    activate AchievementService
    
    AchievementService->>Database: SELECT * FROM UserAchievement WHERE user_id='{userId}' AND achievement_id='NOVICE_CLIMBER'
    activate Database
    Database-->>AchievementService: 📊 업적 상태 조회 결과 { unlocked: true, reward_claimed: false }
    deactivate Database
    
    alt 보상 수령 조건 충족
        AchievementService->>Database: BEGIN TRANSACTION
        activate Database
        
        AchievementService->>Database: UPDATE UserAchievement SET reward_claimed = true, claimed_at = NOW()
        AchievementService->>Database: UPDATE Users SET gold = gold + 100, gems = gems + 5
        
        AchievementService->>Database: INSERT INTO UserTransactionLog (user_id, type, amount, reason)
        AchievementService->>Database: COMMIT TRANSACTION
        Database-->>AchievementService: ✅ 보상 지급 완료
        deactivate Database
```

## **📋 시스템 특징 및 아키텍처**

### **⚡ 하이브리드 랭킹 시스템 특징**
- **실시간 기록 업데이트**: `StageManager.OnBestTimeUpdated` 이벤트 기반 자동 서버 전송
- **3-Layer 캐시 구조**: Redis (서버) + Dictionary (클라이언트) + 자동 마이그레이션 계층 캐싱으로 성능 최적화
- **Top N + 내 기록 분리**: 상위 랭킹과 개인 기록을 별도 조회하여 UI 최적화
- **중복 요청 방지**: `_pendingUpdates` HashSet으로 동일 스테이지 연속 요청 차단
- **Steam 닉네임 연동**: Steam 프로필 정보 자동 동기화 및 표시
- **Facade Pattern**: `HybridRankingService`가 Redis + Database 복잡성을 추상화
- **장애 복구**: Redis 실패 시 자동 DB 폴백, 복구 시 재마이그레이션

### **🏆 업적 시스템 특징**  
- **Facade Pattern**: `AchievementIntegration` 정적 클래스가 복잡한 `AchievementManager`에 대한 단순한 인터페이스 제공
- **느슨한 결합**: 다른 매니저들이 `AchievementManager`에 직접 의존하지 않고 `AchievementIntegration`을 통해 통신
- **통합된 이벤트 채널**: 모든 게임 이벤트가 `AchievementIntegration`을 통해 일관된 방식으로 처리
  - `GameManager` → `OnStageStart()`, `OnPlayerDeath()`
  - `StageManager` → `OnStageCleared()`
  - `ItemManager` → `OnItemUsed()`, `OnItemPurchased()`
- **이중 플랫폼 동기화**: Steam API + 서버 DB 동시 업적 해제로 데이터 무결성 보장
- **실시간 조건 체크**: 게임 이벤트 발생 즉시 업적 조건 검증 및 해제
- **진행도 추적**: 누적형 업적을 위한 상세 진행 상태 관리 (`AchievementProgress`)
- **보상 시스템**: 업적 달성 시 게임 내 재화(골드/젬) 자동 지급
- **오프라인 지원**: Steam API 실패 시에도 서버 DB 동기화로 데이터 손실 방지
- **Delta 동기화**: 배치 처리를 통한 업적 상태 서버 전송으로 네트워크 효율성 최적화
